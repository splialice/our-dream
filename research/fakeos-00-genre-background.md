# Fake OS / 界面游戏 — 类型背景归档

> 归档日期：2026-11-07
> 三个单游戏归档的公共背景。**动笔前先读这份，避免把类型说错。**

---

## 一、这个类型叫什么（现在还没定论，这本身是内容）

| 叫法 | 谁在用 | 状态 |
|---|---|---|
| **Fake OS** | InterfaceX26 活动推动中 | **正在争取成为 Steam 官方 tag，尚未成功** |
| Interface Sims | 同上，官网定义用词 | 别名 |
| Interface Dramas | 同上 | 别名 |
| Found Device games | 同上 | 别名 |
| "desktop dramas" | 更早的散装叫法 | 已过时 |

**官方定义（InterfaceX 网站原文）**：
> "simulates an actual device and/or operating system (desktop, phone, browser, console, etc.) as a major gameplay mechanic"

**翻译**：把真实设备或操作系统（桌面/手机/浏览器/主机）的模拟，作为**主要玩法机制**。

**这个定义的关键在"主要"两个字**：有模拟界面的游戏很多，但界面必须是**玩法的核心**，不是包装。

## 四、先例：Dwarf tag 是怎么成的

**这是"玩家打标签能不能改变 Steam 分类"的唯一样本：**

```
2024 年初
Dwarf Fortress 和 Deep Rock Galactic 的开发者牵头
理由：有矮人的游戏被打散在无关分类里
做法：号召玩家集体给这些游戏打 "Dwarf" 标签
结果：Valve 官方加了 "Dwarf" 这个 tag
```

**InterfaceX26 明确说自己是照这个路子做的**，还做了个网页工具简化打标签流程。

**所以判断标准很干净**：
```
现在去 Steam 搜 "Fake OS" 这个 tag
有 → 成了
没有 → 还在争取
```

**⚠️ 这一条我没验证过。需要你的 agent 去查，或者你手动查。查到的结果直接决定文章怎么写。**

## 五、类型的四条机制分线（我自己的归纳，不是官方分类）

**判断依据不是"像什么"，是"信息怎么到你手上"。**

### A. 检查型 —— 人送上门
```
Papers, Please · Not Tonight · Lil Guardsman
ZeroPrompt（判断内容是 AI 还是人写的，Papers Please 式）
I.T. Never Ends（处理工单，81 个结局）
Need to Know · Quarantine Zone
```
**玩家想要的是**：当把关者

### B. 检索型 —— 你自己去库里搜
```
Her Story · Telling Lies · Immortality
The Roottrees are Dead · Database Detective（真 SQL）
Lost Wiki: Kozlovka · The Operator · Mainlining
Cyber Manhunt · Orwell 系列 · Unheard（纯听觉）
```
**玩家想要的是**：当调查者

### C. 监视型 —— 信息自动流过来
```
Beholder / Beholder 2 · Do Not Feed the Monkeys
Not For Broadcast · Please, Watch the Artwork
The Occupation
```
**玩家想要的是**：当观察者

### D. 沉浸浏览型 —— 环境里翻找
```
Hypnospace Outlaw · Secret Little Haven · Emily is Away
Videoverse · KinitoPET · Simulacra 系列
A Normal Lost Phone · Desktop Explorer · New Folder
Shutter Story · PhotoLoop · No Players Online
Pony Island · Blippo+ · Stories Untold · Bury me, my Love
Home Safety Hotline · Daemon_9
Macellum（玛奇莲超市，中文，要配 Excel）
```
**玩家想要的是**：当考古者

**Note**：很多游戏跨线（Simulacra 既检索又浏览），**分类是给读者用的，不是给游戏用的。**

## 七、这个类型共同的三个设计难题（写深度时用）

**① 手感 vs 真实**
做太真实，玩家会无聊（真的在等页面加载）；做太顺手，就不像那个年代了。
Hypnospace 的做法：加载慢是刻意的，但可以调（无障碍选项）。

**② 自由度 vs 可解性**
Hypnospace 的目录原本想让用户自定义，玩家看不懂；改成企业逻辑分区才好用。
Roottrees 的做法：用"证据直觉"数字告诉你还有几条没用上。
→ **两个游戏都在"让玩家不至于完全迷路"这件事上做了妥协。**

**③ 界面作为叙事，还是界面作为皮肤**
判断标准：**把界面换成一个普通菜单，游戏还成立吗？**
```
Her Story：换成菜单就毁了 —— 检索就是故事
Papers Please：换成菜单就毁了 —— 盖章就是道德动作
反面例子：很多游戏把"手机界面"当皮，换成列表毫无损失
```
